# КАДР / AI

Україномовний сайт конкурсу на Vue та Node.js. Дані зберігаються у `data/votes.json`, база даних не потрібна. Коментарів у коді немає.

## Запуск на комп’ютері

Потрібен Node.js 22.12 або новіший.

```sh
npm install
npm run dev
```

Відкрити адресу Vite з термінала (зазвичай http://localhost:5173). Для виробничої збірки: `npm run build`, потім `npm start` — сайт на порту 3000.

## Учасники та відео

У `config/contest.json` внесено сім учасників із папки «Студенти». Шість фотографій скопійовані у `public/avatars`; для Кривошеєва Олександра фото у джерелі немає, тому показуються ініціали. Групи в наданих матеріалах не зазначені: заповніть поле `group`, коли вони будуть відомі. Восьмого учасника в папці немає; можна додати ще один запис з унікальним `id`.

- `name`, `group`, `title` — дані автора та роботи. Прізвище ставте першим для правильного алфавітного сортування.
- `video` — посилання YouTube, Shorts, youtu.be або пряме посилання TikTok виду `https://www.tiktok.com/@author/video/123...`. Короткі надані TikTok-посилання вже розгорнуті. Для нової короткої TikTok-посилання спочатку відкрийте її у браузері та скопіюйте повну адресу. Старе поле `youtube` також підтримується.
- Відео відкриваються в офіційних iframe-плеєрах. Вони мають бути доступними на платформі та дозволяти вбудовування. У модалці є пряме посилання на випадок недоступності плеєра. Усі сім карток мають справжні прев’ю роликів, збережені локально в `public/previews`. Поле `thumbnail` задає адресу обкладинки. Фото автора не використовується замість кадру з відео. При заміні відео замініть також обкладинку.
- `format` — `portrait` для 9:16, `landscape` для 16:9.
- `avatar` — URL фотографії або `/avatars/name.jpg`; локальне фото покладіть у `public/avatars/` перед збіркою. Без фото показуються ініціали.

Не змінюйте `id` після початку голосування. Після зміни конфігурації перезапустіть сервер. Після додавання локальних фото повторіть збірку. Поки відео не додане, голосування за роботу недоступне. Нові реальні учасники мають окремі ID, тому голоси за колишні демонстраційні записи не приписуються їм.

## Етапи

Поточне голосування закінчується **6 листопада 2026 о 13:10, Europe/Kyiv** (`2026-11-06T13:10:00+02:00`). Час перевіряє сервер. Після дедлайну перший запит фіксує трійку у JSON; навіть якщо сервер був вимкнений у цей момент, пізні голоси не приймаються. Сторінка оновлює лічильники кожні 10 секунд.

Спочатку учасники відображаються за прізвищем в українському алфавітному порядку. Після появи голосів спочатку сортуємо за кількістю голосів, а за однакової кількості — за прізвищем. Це саме правило визначає трійку півфіналістів і відображається у модалці правил.

Другий етап вимкнений. Щоб запустити голосування серед трьох, після відбору встановіть `final.enabled: true`, `final.startsAt` і `final.deadline` у форматі ISO з часовим поясом, потім перезапустіть сервер. Початок має бути не раніше завершення відбору. Голоси нового етапу рахуються окремо; ті самі облікові записи можуть проголосувати ще раз. Не видаляйте `data/votes.json` між етапами.

## Захист

Реєстрація за іменем, email та паролем. Для входу потрібні email та пароль. Email нормалізується, повторна реєстрація на ту саму адресу заборонена, включно з одночасними запитами. Паролі зберігаються через scrypt із випадковою сіллю. Сесії використовують HttpOnly / SameSite cookie, у production — Secure. Сервер відхиляє повторні голоси та запити після дедлайну, обмежує частоту запитів і перевіряє спеціальний заголовок для захисту від CSRF. JSON записується атомарно. Блокування не дозволяє запускати два процеси з одним файлом даних.

На один браузер дозволено не більше двох успішних реєстрацій. Сервер видає випадковий HttpOnly cookie пристрою, а його хеш і лічильник зберігає у JSON. Перевірка повторюється після хешування пароля, тому одночасні запити не обходять ліміт. Вихід з акаунта й перезапуск сервера ліміт не скидають. Невдала реєстрація не витрачає місце. Вхід в існуючі акаунти дозволений.

Email не підтверджується листом. Очищення cookies, інший браузер або приватний режим дозволяють обійти ідентифікатор пристрою; вебсайт не має надійного апаратного ID. Обмеження частоти запитів ускладнює масову накрутку, але не підтверджує особу. IP не прирівнюється до людини: студенти можуть користуватися спільним Wi-Fi. Самостійного відновлення пароля немає.

## Розміщення

Потрібен хостинг **Node.js або Docker із постійним диском**. Статичний хостинг не виконає сервер і не збереже голоси. Запускайте тільки одну репліку сервера. Папка `data` повинна зберігатися між перезапусками та розгортаннями. `config`, `server` та `data` не роздаються браузеру.

Найпростіша конфігурація для Node-хостингу:

1. Завантажте проєкт без `node_modules`, `.git` та локальних тестових даних.
2. Команда збірки: `npm ci && npm run build`.
3. Підключіть постійний диск, задайте `DATA_DIR` шляхом до нього.
4. Команда запуску: `npm start`. Задайте `NODE_ENV=production`, `PORT` за вимогою хостингу.
5. Увімкніть HTTPS. Якщо перед Node стоїть рівно один довірений reverse proxy, задайте `TRUST_PROXY=1`. Не відкривайте порт Node в обхід цього proxy.

Для Docker на сервері з HTTPS reverse proxy:

```sh
docker compose build
docker compose up -d
```

Трафік HTTPS проксі спрямовуйте на порт 3000. `compose.yaml` розрахований на один такий проксі; налаштуйте його відповідно до хостингу. На звичайному HTTP production-cookie не працюватиме: для локального перегляду використовуйте `npm run dev` або `npm start` без `NODE_ENV=production`.

Не запускайте `docker compose down -v`, якщо потрібні голоси: ця команда видалить постійні дані.

Резервну копію `data/votes.json` зберігайте в закритому місці. Не додавайте дані до Git. Перед справжнім запуском використовуйте чисту папку даних, щоб тестові голоси не потрапили до конкурсу.

## Перевірки

```sh
npm test
npm run build
```

Автоматичні тести використовують тимчасові дані, перевіряють реєстрацію, ліміт двох акаунтів включно з одночасними запитами та перезапуском, повторні голоси, сесії, дедлайн, алфавітне сортування, обидва відеоплеєри, відбір трьох і другий етап.

Браузерна перевірка: після збірки `node scripts/check-ui.js`. Вона запускає окремий сервер із тимчасовими даними. Потрібен Chromium для Playwright або `BROWSER_PATH` до встановленого браузера. Перевіряються фотографії, порядок карток, модалки, адреси iframe і мобільна верстка; відтворення залежить від доступності зовнішніх платформ.
